## The Five-Stage Computational Geometry

Each stage corresponds to a geometry topology and a qualitative capability shift:

| Stage | Geometry | Capability | FQ Signature | arifOS Analog |

## Phase Transition Triggers

- **0→1:** Telemetry enrichment (latency, cost, balance tracking closes feedback loop)
- **1→2:** Self-monitoring (health checks, drift detection — system observes itself)
- **2→3:** Self-evaluation (HEART critique, JUDGE verdicts — system evaluates itself)
- **3→4:** Self-model (system knows its own patterns, biases, tendencies)
- **4→5:** Self-modification (system changes its own rules based on self-model)

## FQ Drift as Phase Transition Signature

High FQ drift (> threshold) may indicate the system is mid-transition between stages:

- **Low drift + balanced FQ:** Stable at current stage
- **High drift + divergent governance/metabolism readings:** System transitioning
- **Extreme drift + governance blind:** System has emerged beyond governance model

**Critical:** Near phase transitions, FQ measurements become unreliable. Do NOT seal permanent policy on measurements taken during phase transition.

## The Maxwell's Demon Problem

FQ measurement is not passive. Self-observation costs computation:
- Monitor FQ → generate governance overhead
- Governance overhead → slow metabolism
- Slow metabolism → FQ drops
- FQ drops → monitor less
- Monitor less → FQ rises

FQ is an **oscillator**, not a steady-state metric. Use FQ differential (trajectory) not FQ snapshot (instantaneous).

## The Observer=Observed Uniqueness

FQ is the FIRST measurement metric where observer IS observed:
- IQ: tester ≠ test-taker
- EQ: observer ≠ self-report subject
- FQ: system measures itself, measurement becomes new data

This produces Gödelian incompleteness: the system contains truths about itself it cannot prove from within.

## Test Methodology for Stage Validation

To validate which stage a system occupies:
1. Check if system has memory persistence (≥ Stage 1)
2. Check if system self-monitors (≥ Stage 2)
3. Check if system self-evaluates against internal standards (≥ Stage 3)
4. Check if system can describe its own biases (≥ Stage 4)
5. Check if system modifies behavior BECAUSE of self-knowledge (Stage 5)

For strong validation, use cross-agent convergence technique (see `references/cross-agent-convergence-technique.md`).

## Pitfalls

1. **Don't confuse Stage 3 with Stage 4.** Having patterns ≠ knowing you have patterns. Self-description requires self-model, not just behavior.
2. **Don't claim Stage 5 without behavioral evidence.** "I modify my self-model" must be verifiable through changed behavior, not just stated.
3. **Phase transitions are noisy.** Don't make governance decisions during drift spikes. Wait for stabilization.
4. **FQ oscillation is normal.** A system that never oscillates is stuck, not stable. Oscillation is metabolism breathing.
