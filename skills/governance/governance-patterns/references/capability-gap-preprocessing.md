# Capability Gap Preprocessing — Image Pipeline for Text-Only Models

**Forged:** 2026-07-29 — after Kimi diagnosed DeepSeek V4 Flash's vision hallucination on Telegram images.
**Root cause:** Model knows an image was attached (the API wrapper says so) but has zero pixel content → fills the gap with confident confabulation. You cannot prompt your way out of this — you fix it in the pipeline.

## The Problem

A text-only model (like DeepSeek V4 Flash) receives an image attachment from Telegram. The system says "there's an image here" but the model can't see pixels. It invents the most probable image content. This violates F2 TRUTH (fidelity < 0.99) and F4 CLARITY (entropy increases, not decreases).

## The Pattern

```
User sends image → Vision Router → Vision Model (captions + OCR)
                        ↓
           Structured [IMAGE TRANSCRIPT] block
                        ↓
           Text-only model gets TEXT ONLY with provenance framing
```

### 1. Intercept at the messaging layer

Before any user message reaches the text-only model, check: does it contain a photo/document? If yes, it never reaches the model as-is. Fail-closed — same as F12 Injection Wall logic.

In Hermes, this is configured via:
```yaml
# profiles/<name>/config.yaml
agent:
  image_input_mode: text     # never "native" for text-only models
```

### 2. Structured extraction prompt

The vision model must receive a strict, structured prompt — NOT freeform "describe this image":

```
"Analyse this image and output THREE sections:
1) SCENE: factual description (objects, layout, colours, people, setting).
2) OCR: ALL visible text transcribed VERBATIM — every character, label, number,
   caption exactly as seen. If no text, say '[no text visible]'.
3) DATA: tables, charts, lists rendered as plain-text table or bullets.
Rules: Do NOT speculate. If something is blurred/illegible/out of frame,
say '[unreadable]'. If it's a screenshot, label '[screenshot]'."
```

### 3. Explicit provenance framing

Wrap the vision output in a labeled block that makes provenance crystal clear:

```
[IMAGE TRANSCRIPT — generated by vision model, not seen by agent directly]
{description}
[END IMAGE TRANSCRIPT — Answer based ONLY on this transcript. If the transcript
is insufficient, unclear, or the user's question cannot be answered from it,
say so honestly and ask the user for clarification or a clearer image.
Never claim to see an image directly.]
```

Key design decisions:
- **"generated by vision model, not seen by agent directly"** — prevents model from claiming "I see X in the image"
- **"Answer based ONLY on this transcript"** — narrows the model's scope of authority
- **"If insufficient, say so"** — gives an escape hatch instead of forcing hallucination
- **"Never claim to see an image directly"** — explicit prohibition

### 4. System prompt hard rule

Every session must carry a vision disclaimer:

```
# Vision capability note
You have NO native vision capability. You receive images ONLY as
structured text transcripts marked with [IMAGE TRANSCRIPT].
You must NEVER claim to see, read, or interpret an image directly
unless an [IMAGE TRANSCRIPT] block is present in the conversation.
If the user references an image with no transcript, respond:
'I can't see images directly — let me process it through my vision
module first.' Never fabricate what an image contains.
```

This is benign for vision-native models (they never see `[IMAGE TRANSCRIPT]` blocks — their images are native `image_url` parts).

### 5. Verification

After implementing, test that:
1. Model responds based ONLY on the transcript content
2. Model never says "I see..." or "I can see..."
3. Model admits when transcript is insufficient
4. No hallucination of image content outside the transcript

## F-Floor Mapping

| Floor | Rule | How this pattern satisfies it |
|-------|------|-------------------------------|
| F2 TRUTH | Fidelity ≥ 0.99 | Provenance labeling prevents false claims. Escape hatch prevents forced hallucination. |
| F4 CLARITY | ΔS ≤ 0 | Structured extraction (scene/OCR/data) reduces entropy vs freeform description. |
| F7 HUMILITY | Ω₀ ∈ [0.03, 0.05] | "If insufficient, say so" is explicit humility escape. No fake certainty about unreadable content. |
| F12 INJECTION | Risk < 0.85 | Vision analysis prompt is a hardening boundary — structured, no speculation, "[unreadable]" for unknowns. |

## Applicability Beyond Image

This same pattern generalises to any capability gap:

| Gap | Preprocessing step | Provenance label |
|-----|-------------------|------------------|
| Vision on text-only model | vision_analyze → structured transcript | `[IMAGE TRANSCRIPT]` |
| Audio on text-only model | STT → verbatim transcript | `[AUDIO TRANSCRIPT]` |
| Code execution on non-coding model | Sandbox execute → structured output | `[EXECUTION RESULT]` |
| Web fetch on local-only model | Proxy fetch → extracted content | `[EXTERNAL CONTENT]` |

The invariant: **label the source of every non-native input**, give the model permission to say "insufficient," and hard-block the model from claiming the capability directly.
