# Verifying Computed Claims in Data/Config Artifacts

Companion to the main SKILL.md. That protocol covers runnable *code* artifacts
(extract → run tests → git status). This covers the other recurring shape: an
artifact or receipt that is **structured data with embedded computed values** —
a design-token JSON with a contrast matrix, a financial model with ratios, a
physics config with derived moduli, a receipt table of percentages/thresholds.

The rule is the same as for code: **a self-reported computed value is INT
(interpreted) until you re-derive it yourself.** A table that says "all ratios
pass per the matrix" is a promise, not a measurement.

## Why this catches real errors

Computed-value tables are usually generated by the same agent that wrote the
artifact, often in one pass. The agent that *asserts* "4.76:1 AA" rarely
*recomputes* it before asserting. So errors propagate silently into the canon —
and if the value feeds a CI lint or a governance threshold, the error gets
*enforced*, not just displayed.

**Case (2026-08-01, PRIMER-1 design-tokens):** A forge agent delivered a
design-token JSON with a 13-row WCAG contrast matrix, every row labelled with a
ratio and a verdict ("AAA ✓", "AA caption-only"). Independent re-derivation:

- 12 of 13 rows matched to the hundredth (ink 16.27:1, yellow-900 8.51:1,
  blue-700 12.23:1, muted 5.59:1, full carbon matrix 17.52/12.40/9.82/7.31,
  both catastrophe pairs 1.41/1.78, both trap claims 3.04/5.13).
- **1 row wrong:** teal-900 `#064E3B` on paper `#FAF7F0` claimed **4.76:1
  "AA caption-only"** — actual **9.08:1, AAA full-body text.**

The error was *over-restriction*, not a safety failure — but it mattered because
the value appeared in two places (`domain_accents.earth.primary.role` and
`contrast_pairs.matrix_paper_text`) and would have driven a CI lint that
downgraded earth-domain text to caption-only on its own canvas for no reason.
Two-line fix; caught only because the math was re-run.

**Lesson:** the error was the same class the `contrast_pairs` section was built
to prevent — an unverified number baked into canon. The verifier is the thing
that makes the artifact's own honesty claims true.

## The technique

1. **Extract the claim table.** Pull every (input → computed value → verdict)
   triple from the artifact. Don't trust the verdict column — recompute the
   value, then apply the threshold yourself.
2. **Re-derive from first principles with your own code.** Use `execute_code`.
   Implement the formula independently (don't copy the artifact's helper — it
   may carry the same bug). For WCAG that's the relative-luminance formula;
   for finance it's the ratio definition; for physics the modulus equation.
3. **Build a MATCH/DISCREPANCY table.** Columns: pair, claimed, mine, Δ,
   verdict. Tolerance ~0.01–0.15 depending on rounding. Flag every |Δ| beyond
   tolerance.
4. **Classify each discrepancy.** Over-restriction (safe but wrong, wastes
   capability) vs under-restriction (unsafe, passes something that should
   fail). Under-restriction is the dangerous one — it means a bad value is
   being waved through.
5. **Check propagation.** Grep the whole artifact for the wrong value — it
   usually appears in more than one place (a `role` string AND a matrix entry).
   Fix all occurrences or the canon stays internally inconsistent.
6. **Confirm the verdict column independently.** Don't just check the ratio —
   re-apply the threshold (WCAG: ≥7 AAA, ≥4.5 AA, ≥3 AA-large) and confirm the
   labelled verdict matches. A correct ratio with a wrong verdict label is
   still a defect.

## Reusable WCAG contrast verifier

Drop-in for any design-token / color-canon audit. Independent implementation of
WCAG 2.x relative luminance + contrast ratio.

```python
import json

def lin(c):
    c = c / 255.0
    return c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4

def lum(hexstr):
    h = hexstr.lstrip('#')
    r, g, b = int(h[0:2], 16), int(h[2:4], 16), int(h[4:6], 16)
    return 0.2126 * lin(r) + 0.7152 * lin(g) + 0.0722 * lin(b)

def contrast(fg, bg):
    l1, l2 = lum(fg), lum(bg)
    return (max(l1, l2) + 0.05) / (min(l1, l2) + 0.05)

def wcag_verdict(ratio, body=False):
    # body=True applies the stricter AAA-body rule (>=7)
    if ratio >= 7:   return "AAA"
    if ratio >= 4.5: return "AA"
    if ratio >= 3:   return "AA-large"
    return "FAIL"

# claims = [(label, fg_hex, bg_hex, claimed_ratio, claimed_verdict), ...]
claims = [
    ("ink on paper",        "#1A1A1A", "#FAF7F0", 16.27, "AAA"),
    ("teal-900 on paper",   "#064E3B", "#FAF7F0",  4.76, "AA caption-only"),
    # ... one row per claim in the artifact's matrix
]

print(f"{'Pair':<28} {'Claimed':>8} {'Mine':>8} {'Δ':>7}  {'Verdict':>10}  Status")
for label, fg, bg, cr, cv in claims:
    mine = contrast(fg, bg)
    delta = mine - cr
    ok = abs(delta) < 0.15
    print(f"{label:<28} {cr:>8.2f} {mine:>8.2f} {delta:>+7.2f}  "
          f"{wcag_verdict(mine):>10}  {'MATCH' if ok else 'DISCREPANCY'}")
```

## Generalizes beyond color

Same protocol for any artifact that ships a table of computed numbers:

| Artifact type | Re-derive with |
|---|---|
| Design tokens / color canon | WCAG luminance + contrast (above) |
| Financial model / health metrics | ratio definitions (runway, burn, NPV, EVOI) |
| Physics / geomechanics config | modulus / impedance / stress equations |
| Statistics / scoring rubric | the weighting + normalization formula |
| Receipt table of % / thresholds | whatever produced the number — ask if unclear |

If the artifact doesn't show its inputs (hexes, cash flows, densities), pull
them from the artifact's own data sections first — the verifier should read the
artifact's inputs and recompute, not re-type them (re-typing introduces your
own transcription error).
